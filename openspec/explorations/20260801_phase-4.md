# Exploration log

## 2026-08-01 — Phase 4 clarifications (wave lifecycle, bankruptcy redesign, win/lose)

Q&A pass over Phase 4 scope, biggest blast radius first. Decisions:

- **Wave lifecycle — strict sequential.** A wave is active from start-wave until every enemy
  it spawned is dead or escaped (carriers walking out included). Then settlement: unclaimed
  sacks return, interest stops, start-wave re-arms. No overlap, no early call. "During waves"
  and "end of wave" everywhere mean this state machine.
- **Dormant spawns — validate all spawns from tick 0.** Placement reachability includes
  inactive/future spawns, so the no-sealing invariant survives mid-run activation. Carrier
  *escape* pathing stays active-spawns-only (two different spawn sets, deliberately).
- **Theft overdraws the treasury.** Remove phase-2's `max(0, …)` clamp in the grab: inbound
  enemies always take full carryCapacity, driving balance negative. Matches README line 55;
  archived phase-2 theft spec needs an amendment. Killing the carrier drops the sack and
  end-of-wave return restores the gold — deep raids are survivable iff the maze stops carriers.
- **Bankruptcy redesigned — no −100 threshold.** Replaced by a *solvency gate on start-wave*:
  cannot start the next wave with balance < 0; the only between-wave income is selling
  structures (0.5 refund), so paying debts means weakening defense — the death spiral is the
  mechanic itself. README line 55 and ROADMAP "lose at −100" need rewriting.
- **Lose trigger — manual concession only.** No auto-lose on insolvency; the run sits locked
  until the player gives up. UI mitigation (for the newcomer gate): when total liquidation
  value < |debt|, the give-up control must state that recovery is impossible.
- **Win — solvent to win.** After wave 10's settlement, victory fires only at balance ≥ 0;
  if negative, the same locked sell-to-recover state applies and the win fires on reaching
  solvency (concede remains available). One uniform rule: solvency is always the ticket forward.

Remaining items judged proposal-level defaults, not user decisions: interest fixed-point
accrual detail (per-tick on positive mg balance, waves only — rate is a playtest knob),
wave-preview UI scope, which wave introduces the brute, run-summary stat definitions,
and whether the terrain palette (below) rides as phase 4's first chunk (lean: yes).

## 2026-08-01 — Terrain palette, sockets, and structure visuals (toward Phase 4)

Prompted by: "navigable parts dirt, non-navigable grass (aesthetically), tower-square-bottom-b
as buildable parts on non-navigable grass."

**Rejected reading:** fixed-path TD (enemies confined to authored dirt, towers only on sockets)
— would contradict README goal #1 (dynamic maze-building). Explicitly off the table.

**Decisions:**
- Terrain becomes a four-kind authored palette replacing the binary blocked mask:
  - `dirt` — navigable, player-buildable (walls + towers); the maze space
  - `grass` — non-navigable scenery (`tile` model)
  - `rock` — non-navigable scenery (`tile-rock` model)
  - `socket` — non-navigable, towers only; renders as grass + `tower-square-bottom-b` base
- Navigable ground renders as `tile-dirt` (already in public/models); "navigable" means
  authored-open, not dynamic reachability — ground stays static.
- Wall model = `tower-square-bottom-a` (replaces placeholder wall mesh). With phase-3 D1
  (towers are 1×1 wall segments that shoot), a tower visually reads as a wall that grew a gun;
  socket's bottom-b variant reads as world-built vs player-built masonry.
- Dirt stays dirt under player-built structures — dirt = player domain (mutable),
  grass/rock = world (immutable). Keeps `ground.ts` build-once, no reactive rebuild.
- Socket placement skips reachability/re-path validation entirely (tile already blocked);
  socket towers consume no maze space and can't be routed around, so socket count/position
  is a pure level-authoring balance knob (and a teaching tool for wave design).
- Level schema: replace `terrain.blocked` coordinate list with a char-map (`terrainMap` +
  legend) for hand-authorability; spawns/treasury stay coordinate objects (metadata).
- `tower-square-bottom-b.glb` exists in the kit but is NOT yet in public/models — needs copying.

**Sequencing:** land as first chunk of Phase 4 (or standalone right before it), after
phase-3-combat — it shares files with phase 3 (`placement.ts`, `towers.ts`) and phase 3's
34 tasks are already authored against current code.

**Open questions:**
- Walls on sockets: lean no (tile already blocked; sockets accept towers only).
- Removal delay for socket towers: juggling-prevention rationale doesn't apply; lean keep
  uniform 4 s for rule simplicity.
- Re-author level_01 with the full palette in the same change, or debut it in level_02?
  Lean re-author level_01 (it's the teaching level).
